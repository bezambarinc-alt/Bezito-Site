Atelier Story — /the-story — SHIPPED
Architecture decision (2026-07-25):
This is a new page build — src/pages/the-story.astro with its own Astro template. Verdura uses data-template="page.story", a dedicated page type — not a modified About page. For Bez Ambar: the new /the-story route is the immersive timeline experience. The existing /about-bez-ambar stays as credential/positioning copy. Two destinations, two purposes.

What the Verdura reference means (full analysis 2026-07-25):
verdura.com/pages/the-story is a scrollable vertical timeline with 16 dated chapters from 1899–2018. Each chapter = (1) named person, (2) specific piece tied to a real moment, (3) outcome. "Joan Fontaine purchases the pink topaz Wing brooch — later wears it in Hitchcock's Suspicion." That specificity is the whole point. Chapter-break full-bleed images (4 total) separate major eras. Ends with newsletter signup — not a product CTA. The conversion pipeline is: brand immersion → email capture.

Technical build path:
— src/pages/the-story.astro — new page, own template, stripped nav (no persistent CTA rail)
— src/data/story-timeline.json — chapters: { year, headline, body, images[], layout }
— CSS vertical line system + scroll-animated element entry (IntersectionObserver already in codebase)
— Sticky year nav (JS reads data-year attributes, populates nav dynamically — ~20 lines)
— Footer: newsletter signup, no product links

Content inputs needed from Bez before building:
— Timeline anchors: key years with specific context — not just "1979 arrived in LA" but what happened, who was there, what piece came out of it

Site Command System

What these commands do and how to use them. Say the natural trigger phrase to Bezito and the right command fires. All scripts live in web/bez-ambar/scripts/admin/

🔄 Two Pipelines
Pipeline 1 — Products Assets → Cloudinary → Plytix (Completed) → 4h sync → Neon → bezambar.com
active + featured = Neon-only flags via admin API — never set in Plytix. Neon products table is a read cache — never write manually.
Pipeline 2 — Client Pages Bez instruction → POST /api/admin/pages → /preview/[slug] → portal or PIN
Proposals = portal login (email + password). Showcases = client generates 4-digit PIN, shares with their customer.
🔐 Auth & Security
All scripts use JWT bearer tokens minted from BEZITO_SECRET in .env.local. Tokens are HS256, 15-min expiry, signed at script load.

_env.mjs handles loading — import agentHeaders() for all fetch calls. Never commit BEZITO_SECRET to repo.

Idempotency: Create scripts send Idempotency-Key: uuid — safe to retry on network errors, no duplicate records.

Direct Neon reads: BEZITO_NEON_READONLY_URL gives SELECT-only DB access — bypasses HTTP for fast lookups.
