Security Hardening — 2026 Best Practices
Full security audit against 2026 Next.js guidance (authgear.com, workos.com, safeguard.sh). All gaps fixed:
  • server-only — lib/auth.ts + lib/db.ts throw at build time if accidentally imported client-side. Prevents secret leakage into browser bundle.
  • Zod validation — all auth endpoints validate + type-check input server-side before touching the DB.
  • Rate limiting — DB-backed (Neon), 5 attempts / 15 min per IP. No external service needed. Returns 429 + Retry-After header.
  • Audit logging — every login success/fail, PIN success/fail, user add/remove, PIN change writes to the existing audit_log table.
  • Open redirect protection — ?from= redirect param validates same-origin only. Prevents session-hijack via crafted login URLs.
Migration 003 (login_attempts table + indexes) applied to Neon.

Full Auth System — PIN + Email/PW, Admin Settings UI, DB-Backed
Complete from-scratch auth system:
  • Login page — two tabs: PIN (numeric, large) | Sign In (email + password). Loading states, no double-submit, redirect-back to original URL after auth.
  • PIN auth — hashed with bcrypt, stored in admin_settings DB table. Never plaintext anywhere.
  • Email/PW auth — hashed with bcrypt, stored in admin_users DB table. Replaces env-var credentials.
  • Logout — Server Action (CSRF safe), clears cookie, redirects to /login.
  • /admin/settings — manage PIN and users from inside the admin. Add/remove users, change PIN. Self-delete protection. Can't remove last user.
  • Settings added to AdminNav.
Migrations 002 applied to Neon. Credentials seeded (hashed). Designed to slot CF Access in cleanly — one env var swap in proxy.ts.

29dc2c2
Timing-Safe Password Compare
Fixed brute-force timing attack in login route. Plain string compare (user.pass !== password) replaced with crypto.timingSafeEqual on SHA-256 hashes. Both inputs hashed first to guarantee equal-length buffers. No new dependencies — Node built-in crypto only. (Later superseded by bcrypt migration in 21ec4d7.)

Architecture
CF Access — Design + Research
Researched and documented the production auth architecture using Cloudflare Access (Zero Trust Free tier, up to 50 users):
  • Whitelisted IPs → PIN-only (email OTP via CF) → 8h session
  • External → email + password + independent MFA (TOTP/security key) → 2h session
